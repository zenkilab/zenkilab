# Automotive logo catalog (internal)

This branch adds source intake, an SVG-to-relief pipeline and inquiry-only emblem previews. It does not change the approved Mercedes geometry, deploy a listing, or grant trademark rights.

## Evidence and rights

`manifest.json` separates source verification, technical support, asset copyright/license status, and commercial trademark authorization. **Every brand is commercially unverified and inquiry-only.** Cardog's repository says MIT but reserves asset ownership to the respective owners. VehicleSpecs limits MIT to organization/metadata. Diego Jasso attributes SVGs broadly to Wikimedia Commons without per-file license provenance. Commons is a discovery category, not a blanket license for its contents. No original manufacturer/Commons file identity was established for these selected upstream files; that gap is explicitly recorded. These are freely downloadable research references, not a commercially cleared manufacturing library.

The pinned source-tree versions, original URLs, byte hashes and sanitized hashes are in the manifest. Downloaded repository metadata, README and license snapshots are in `reports/`. Selected sources are Cardog Icon variants rather than Logo/Wordmark variants; Suzuki was fetched from VehicleSpecs. Mercedes uses the existing custom ridged provider and is never flattened or regenerated by this pipeline.

Source investigations:
- https://github.com/cardog-ai/icons
- https://github.com/vehiclespecs/brand-logos
- https://github.com/diegojasso/car-logos-SVG
- https://commons.wikimedia.org/wiki/Category:SVG_logos_of_car_symbols

## Reproduce

1. `python automotive-logo-catalog/source/intake.py`: strict element/attribute allowlist, rejecting scripts, events, declarations, external resources, styles and unsupported constructs. Raw originals are retained locally, never served. Local safe SVGs are separate. Malicious input smoke tests are included.
2. Serve the project locally on 8771: `python -m http.server 8771 --bind 127.0.0.1`.
3. Set `PLAYWRIGHT_MODULE` to an existing installation and run `node automotive-logo-catalog/source/outlines.cjs`. This uses the existing Three.js SVGLoader inside a local browser, preserving transforms, holes and SVG fill rules before sampling curves. No package is added.
4. `python automotive-logo-catalog/source/generate.py`: normalize actual emblem bounds proportionally into 15 x 15 mm, repair invalid polygons with buffer(0), union overlapping contours, screen 0.4 mm strokes, and build the same 58 x 28 mm capsule/R5 bodies and four border dimensions using the prior solid/export helpers. SVG relief is 0.48 mm. No artificial ridge is added to an asset without approved sculpted geometry. Mercedes retains its existing ridge provider.

Current technical samples: Toyota, Honda, Audi, Mitsubishi and Hyundai. Forty configurations cover both shapes and none/thin/bold/double borders. Nissan and Kia need emblem-only/lettering review; BMW and Suzuki were rejected for unsupported SVG markup. Exact reasons are in the manifest. Rejection is conservative and does not imply the original artwork is defective. Mercedes remains technically supported separately. All cases still require visual approval and a physical first article; recognizable contours in previews are not a manufacturing guarantee.

`gallery.html` shows source/support/rights states and front/back sample renders. The customer preview selector shows accepted sourced icons but does not pretend that a new brand has a customer-approved generated order. No mark is offered for purchase. Technical samples stay outside public assets; only sanitized source icons enter `public/automotive-logos`.

## Printing / validation

Internal samples use white PETG body, navy relief/registration/border, and recessed back branding. Use dry compatible PETG, P2S 0.4 mm nozzle, 0.16 mm body layers, 0.12 mm upper detail if desired, supports off pending slicer review. Navy begins at Z=3.20 mm, requiring one white-to-navy transition. Recesses on the underside require small bridges and optional paint fill; a later filament change cannot color them. The original Mercedes flush-back option is untouched.

`reports/geometry.json` records scale-stroke loss, art containment, text/border clearance, zero color overlap, volume, estimated model mass and mesh topology. `reports/serialized.json` independently checks exported STL meshes and 3MF archive/material meshes. Geometry-only 3MF is unsliced and not printer-ready. Material estimates exclude startup, purge, tower and brim. Purge quantities cannot be calculated reliably without Bambu Studio profiles and slicing; do not infer them from tiny accent mass. Separate meshes retain common coordinates for AMS assignment. Multicolor detail layers in colored source artwork are deliberately flattened to one navy silhouette in current samples; source colors remain preserved in outline data for future reviewed partitioning.

## Current customer-facing two-tone update

The feature branch now uses `web-manifest.json` and `src/lib/automotive-logo-definitions.json` as the web capability/provenance catalog. There are 16 actual artworks: Toyota, Mercedes-Benz, Honda, Nissan, Suzuki, BMW, Audi, Mitsubishi, Hyundai, Kia, Lexus, Mazda, Volkswagen, Ford, Subaru and Isuzu. Kia/Isuzu use recognizable manufacturer lettering marks where no separate verified emblem was selected; Ford retains its oval script badge. Original files, pinned tree versions, hashes and license snapshots remain local. White areas become body color and colored/black artwork becomes accent color; source gradients are flattened for a two-filament appearance. Assets are normalized to actual artwork bounds without aspect distortion and served locally.

Only Mercedes is **CAD validated**, and even it remains commercially unverified and inquiry-only. All other web definitions are **logo sourced / CAD pending**. The earlier flat-extruded experimental samples and old technical manifest are historical research, not approved authentic sculpted profiles or production readiness. This update generates no additional manufacturing geometry. Mercedes's web emblem outline is derived from its approved local provider; the approved STL/3MF bytes are unchanged.

The region/profile interface is `src/lib/automotive-logo.ts`: source artwork, proportional target box, independent region construction, nullable crown/bevel values, corrections, feature-width target, two mesh groups, validation checklist and separate rights/readiness states. Pending values are deliberately null, not invented universal bevels. New CAD is commissioned and validated per brand when requested. The legacy `generate.py` is an experimental SVG extrusion tool and must not be used to claim brand-specific sculpted approval.

`source/web-intake.py` adds safe inline presentation: XML parsing, no DTD/entities/events/scripts/external references, restricted style-to-attribute conversion and only local fragment clip references. It preserves raw originals. `source/normalize-web.cjs` crops safe assets to artwork bounds and updates checksums. Run both in that order; normalization uses existing Playwright against a local project server on 8771. No dependency was added.

The same unlisted configurator now has searchable keyboard-operable thumbnails, body/accent swatches, shape/border selection, proportionally fitted Montserrat registration, optional notes and custom brand/model requests. White/navy is the existing preset, not a stock guarantee; black/silver/red are explicitly proposed. No reliable inventory was found. Contrast below 3:1 blocks the inquiry link and displays a warning. Colors apply to emblem, registration, border and the optional back-fill appearance. There are exactly two color roles and no checkout.

Mercedes CAV 3883 uses its existing 3D raster renders, recolored locally on canvas while retaining shading. Other registrations/brands use a clearly labeled **2D concept**, with no claim of sculpted or printable CAD. Concept text uses the same font outlines and 25 x 6 mm fitting region, with established shape/border dimensions. Changing a concept does not manufacture or certify geometry; per-order collision/feature validation remains mandatory. Metallic filament response and precise surface finish cannot be guaranteed by screen colors.

The back preview shows accent branding. Actual recessed lettering requires paint fill after printing or a separately assigned flush inlay in the first layers; a later filament change cannot reach the underside. The existing two-material Mercedes archives remain unchanged and unsliced.

Inquiries use the existing verified WhatsApp destination and include brand/model, registration, shape, body and accent colors, border, notes, capability/rights review and instructions to attach SVG/STL/reference artwork afterward. No new upload endpoint or unnecessary customer data collection was introduced. No messages are sent by QA. Mercedes CAV 3883 retains Send My Preference; other sourced brands show Request This Design, custom requests show Request Your Car Logo.

Local/live regression script: `source/check-twotone.cjs`, with existing `PLAYWRIGHT_MODULE` and optional `PREVIEW_URL`. Reports/screenshots include all five widths and Toyota/Honda/Mercedes examples. Low-contrast, invalid-registration, custom notes, search, source paths, front/back and WhatsApp payloads are checked. Approved Mercedes archive hashes are verified independently against their existing validation report. General keytag files, sitemap, production workflow and main branch are untouched.
